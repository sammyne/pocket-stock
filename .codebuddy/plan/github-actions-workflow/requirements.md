# 需求文档

## 引言
本文档定义了口袋股票看板（pocket-stock）项目的 GitHub Actions CI/CD 流水线需求。该流水线将自动化代码质量检查、测试执行和代码规范验证流程，确保每次代码变更都符合项目标准，并通过持续集成保证代码质量。流水线将在向 main 分支提交 Pull Request 时触发，帮助团队在合并代码前发现潜在问题。

## 需求

### 需求 1：流水线触发机制

**用户故事：** 作为一名开发者，我希望在向 main 分支提交 PR 时自动触发 CI 检查，以便在代码合并前及早发现问题。

#### 验收标准

1. WHEN 开发者创建或更新指向 main 分支的 Pull Request THEN 系统 SHALL 自动触发 GitHub Actions 工作流
2. WHEN 工作流触发 THEN 系统 SHALL 仅对发生变更的文件执行相关检查以提高效率
3. IF PR 来源分支不是 main 分支 THEN 系统 SHALL 正确识别并执行完整的工作流

### 需求 2：代码质量检查

**用户故事：** 作为一名维护者，我希望工作流自动执行代码规范检查，以便确保所有提交的代码都符合项目的编码规范。

#### 验收标准

1. WHEN 工作流开始运行 THEN 系统 SHALL 使用 ruff 对代码进行 linting 检查
2. WHEN ruff 检查发现代码规范问题 THEN 系统 SHALL 标记检查为失败并显示详细的错误信息
3. WHEN 工作流开始运行 THEN 系统 SHALL 使用 ruff 对代码进行格式化检查
4. WHEN ruff 格式化检查发现格式问题 THEN 系统 SHALL 标记检查为失败并显示需要格式化的文件列表
5. WHEN 工作流开始运行 THEN 系统 SHALL 使用 mypy 对代码进行静态类型检查
6. WHEN mypy 检查发现类型错误 THEN 系统 SHALL 标记检查为失败并显示类型错误的详细信息

### 需求 3：自动化测试执行

**用户故事：** 作为一名开发者，我希望工作流自动执行所有单元测试和集成测试，以便确保代码变更不会破坏现有功能。

#### 验收标准

1. WHEN 工作流执行到测试阶段 THEN 系统 SHALL 使用 pytest 运行所有单元测试
2. WHEN 工作流执行到测试阶段 THEN 系统 SHALL 使用 pytest 运行所有集成测试
3. WHEN 测试执行完成 THEN 系统 SHALL 生成测试覆盖率报告
4. IF 测试覆盖率低于 80% THEN 系统 SHALL 标记检查为失败并显示当前覆盖率
5. WHEN 任何测试失败 THEN 系统 SHALL 标记检查为失败并显示失败的测试详情

### 需求 4：依赖管理和环境准备

**用户故事：** 作为一名开发者，我希望工作流自动安装项目依赖并设置 Python 环境，以便无需手动配置即可执行检查和测试。

#### 验收标准

1. WHEN 工作流开始运行 THEN 系统 SHALL 使用 uv 安装项目依赖
2. WHEN 工作流开始运行 THEN 系统 SHALL 设置 Python 3.13 运行环境
3. WHEN 依赖安装完成 THEN 系统 SHALL 验证所有依赖项已正确安装
4. IF 依赖安装失败 THEN 系统 SHALL 标记工作流为失败并显示错误信息
